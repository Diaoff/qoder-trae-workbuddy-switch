## ✨ 新增

- 网关新增「模型降级链」：主模型在上游明确失败时，按你配置的链自动改用备选模型重发一次。最多 2 跳，每请求每个模型只试一次；在「网关 → 模型」分区里配置，保存即生效（不用重启网关）。
- 降级链支持六种触发条件：模型闸门暂停、模型级限流（6004）、模型被封禁（11102）、上游 5xx、请求超时、模型不存在（404）。可按需勾选，没勾的不会触发。
- 降级链卡片会实时标出每个备选此刻的状态（正常 / 闸门暂停中 / 已禁用 / 不支持图片输入），并在保存前给出「模拟路径」—— 不用真发请求就能看到会怎么降。
- 三个网关（WorkBuddy / Trae / Qoder）都支持降级链，配置各存各的。
- 降级流水：卡片里能看最近几十次降级记录（什么时候、从谁降到了谁、为什么触发、耗时多久）。记录按网关分开。
- 新增「近 7 天降级统计」：在卡片顶部直接看到这段时间降级了多少次、成功多少次、失败多少次。
- 客户端会收到三个响应头标明实际使用的模型（`X-Buddy-Fallback-From` / `-To` / `-Reason`）；降级失败时，错误体里也会带上同一份信息。

## 🐛 问题修复

- 上游「请求超时」此前与「上游 5xx」混成一档，导致「超时换模型」这一降级条件永远选不中。现在超时单独成档（对外返回 504），冷却处置与 5xx 一致、但降级判据独立。
- 降级失败时，此前错误消息里只会看到「账号库为空」，完全看不出网关已经试过备选模型。现在错误体里会带下降级轨迹（从谁降、试了谁、为什么）。
- 带图片的请求不再被降到「不支持图片输入」的备选模型上（否则用户会收到一个必然失败的请求）。

## 🛠 其他

- 版本号统一为 2026.10.291453（全部载体校验通过）。
- 内部实现：降级链的配置与判定收敛到单一模块；降级循环与账号换号循环分层，配额判定与探针归还按「每请求一次」处理，不会因降级而多扣配额或卡住模型。
