## ⚠️ 升级前必读：webui 管理面现在需要密码

- Docker / 服务端形态**升级前必须先设 `BUDDY_SWITCH_PASSWORD`**，否则新镜像会**拒绝启动**（退出码 2，日志会说明怎么补）。老容器换新镜像后起不来的唯一原因就是这条。
- 语义：这个变量只在**首次启动**生效 —— 它把密码写成加盐 sha256 存进 `webui_auth.json`，明文不落盘；之后改密码走界面「设置 → 权限与诊断 → WebUI 密码」，改 compose 里的旧值并重启**不会**改掉密码。
- 本机回环（默认 `127.0.0.1`）**仍然免密**，桌面 App 与本地 `buddy-switch` 用法一行都不用改。
- 忘了密码：删掉数据目录里的 `webui_auth.json` 重新设置该变量即可（容器里是 `/data/.buddy-switch/webui_auth.json`）。

## ✨ 新增：管理界面登录

- `/api/*` 现在需要登录：访问时先看到登录页，输入密码后进管理界面。登录态是 `HttpOnly` Cookie（JS 读不到），12 小时滑动续期，进程重启即全部失效。
- **保护边界是明确的**：网关的 `/v1/*` 与各独立网关端口**不受影响**（它们用自己的 `sk-*` Key 自鉴权，客户端程序照旧直连）；静态资源与 `/healthz` 也免鉴权 —— 后者是容器 healthcheck 的探活点。
- 登录页带 `?next=` 回跳，从外部链接进深链不会丢目标；连续 8 次密码错误锁定 10 分钟。
- 设置页新增「WebUI 密码」卡：改密码需先输旧密码，改完**所有设备**（含当前这台）都要重新登录 —— 这是「旧凭据作废」的正确语义。
- 若你已有反代鉴权、或容器根本不对外映射端口，可以用 `BUDDY_SWITCH_ALLOW_UNAUTHENTICATED=1` 显式承认风险并跳过启动护栏；每次启动都会打红色告警，公网直连**严禁**开启。

## 🐛 问题修复

- Loomy 网关页在「独立网关 / 统一网关」之间切换时界面不再原地不动：子导航改由类型驱动，切到「统一网关」会正确显示它自己的分区。
- Docker 的 healthcheck 从 `/api/status` 改到 `/healthz` —— 前者属管理面，加了密码后必然 401，会让容器永久 `unhealthy`（而服务其实完全正常）。

## 🛠 其他

- `docker-compose.yml` 的 `BUDDY_SWITCH_PASSWORD` 用 `${…:?}` 取值：缺变量时 `up` 会立刻报错并说明怎么设，而不是起一个没人知道密码的容器。`.env` 已加入 `.gitignore`。
- 新增两条构建门禁：healthcheck 不得打受保护路由；鉴权路由不得进 `ROUTES` 表（登录对桌面端无意义，误加会让桌面端报 command not found）。
- 版本号统一为 2026.10.231202（全部载体校验通过）。
