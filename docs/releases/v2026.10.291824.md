## ✨ 新增

- 降级链现在可以**跨平台**：WorkBuddy 的模型失败后可以降到 Trae 或 Qoder 的模型，Trae / Qoder 也能反过来用别的平台兜底。配置时先选平台、再选模型。
- 降级链可以**跨区域**：同一个平台的国内版和国际版之间可以互相兜底（例如 WorkBuddy 国内号限流时自动改用国际版）。
- 每跳的账号轮换次数现在可配（1–6，默认 3）。
- 新增「总请求预算」：一次请求在所有跳与所有账号轮换上的上游请求数合计不超过 8 次。它比「最多试几个模型」更贴近实际耗时——避免配了很长的链却让客户端等到超时。
- 降级链最多可配 3 个备选（原来 2 个）。

## 🐛 问题修复

- 跨平台降级成功后，这次请求现在会出现在请求日志里（此前它被直接透传，日志与用量都漏记）。
- Anthropic（`/v1/messages`）与 Responses（`/v1/responses`）入口不再尝试跨平台降级——目标平台只输出 OpenAI 格式，那两个入口的客户端会解析失败，比不降级更糟。它们仍支持同平台内的降级。
- 请求体里没有 `model` 字段时不再尝试跨平台降级（此前会「改写失败但声称降级了」）。

## 🛠 其他

- 版本号统一为 2026.10.291824（全部载体校验通过）。
- 跨平台降级最多嵌套一层：A 平台降到 B 平台后，B 平台内部不会再跨平台。超出时返回 502 并说明原因，不会无限递归。

## 已知限制

- 跨平台降级的判据只能看 HTTP 状态码（429 / 5xx），因为目标产品线的入口不暴露上游事件类型。这与 Trae / Qoder 自身中继的判据同一档。
- 跨平台降级的请求在入口账本里 token 记 0（响应由目标平台封装，本入口拿不到用量）；目标平台自己的账本会记它那一边的真实用量，所以总量与归属都是对的。
- 配置跨平台备选时需要手填目标平台的模型 id（各平台的模型清单结构不同，不做跨平台自动补全）。填错会得到目标平台自己的 404。
