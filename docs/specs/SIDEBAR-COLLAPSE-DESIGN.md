# 侧栏折叠设计（只显示图标）

> 状态：**已落地**（真机 + 原型同形，2026-10-22）
> 起因：用户截图反馈「功能集成到这个位置太拥挤」—— 侧栏固定 240px，
> 在 1440 宽的窗口上占到 17%，而**内容区才是被看的对象，侧栏是导航**。
> 真机：`src/App.tsx` 的 `<aside>` + `src/lib/sidebar.ts`；
> 原型：`docs/prototype/index.html` 的 `.sidebar` + `demo-app.js` 的 `renderSidebar()`；
> 校验：`docs/prototype/verify-sidebar-collapse.cjs`（5 条断言 + 3 个变异）。

---

## 1. 决策与理由

| # | 决策 | 理由 |
|:--|:--|:--|
| S1 | 两态宽度：**240px ↔ 64px**，不做三档（更窄/更宽） | 64px = 34px 图标 + 两侧 15px，与顶栏 `.icon-btn` 的 34px 同源；再窄图标会贴边，再宽就失去「收起」的意义 |
| S2 | 只过渡 **`width` 一项**（`transition-[width] duration-200 ease-out`） | `all` 会让 border、padding 一起动，视觉上整条侧栏在「抖」 |
| S3 | 开关放在侧栏**最底部**（版本行之下），不放顶部品牌区 | 品牌区是身份区，不放控件；底部边缘是「抽屉把手」的位置（VS Code 同款思路）。收起时按钮自己变成「展开」⇒ 图标翻转、位置不动 |
| S4 | 快捷键 **⌘/Ctrl+B** | 与 ⌘K（命令面板）、⌘1..9（切作用域）同族同规则：必须带修饰键、不接受 alt/shift 组合、输入框内不接 |
| S5 | 折叠是**纯渲染层偏好 ⇒ localStorage**（`buddy-switch.sidebarCollapsed`） | 按读者选层：只有前端读它，没有第二个消费者 ⇒ 不进 core `app_prefs.json`（那条路是给「宿主也读」的偏好留的，如 `close_to_tray`） |
| S6 | **不做「窗口过窄自动收起」** | 不替用户决定。有人就想要宽侧栏 + 滚动内容区；自动收起还会在投影仪/分屏场景反复横跳 |

## 2. 折叠态各元素的处置

| 元素 | 展开 | 折叠 |
|:--|:--|:--|
| 品牌块 | 图标 + 双行文字 | **只留图标**（居中），品牌名进 tooltip |
| 导航项 | 图标 + 文字 + 行尾徽章 | **只留图标**（34px 方钮居中），文字不渲染；hover 出右侧 tooltip（带徽章数） |
| 徽章 | 行尾横排（`账号 4`） | **图标右上角标**（14px 小圆 + `ring-2` 描边隔出层次）—— 64px 里横排放不下，而角标是「有未读」的通用语言 |
| 打赏入口 | 图标 + 文字 | 34px 图标钮 + tooltip |
| 版本行 | 状态点 + 版本号 + 两个小钮 | **版本号文字隐藏**，状态点与两个小钮保留 —— 「客户端在不在跑」是随时要瞟一眼的 |
| 折叠开关 | 图标 + 「收起侧栏」 | 只有图标（PanelLeftOpen），tooltip 说明 |

**为什么徽章要转角标而不是直接隐藏**：账号数 4、网关密钥数 5 是「有事要处理」的提示，
折叠后看不到 = 用户错过待处理事项。角标把「数字还在、只是换了位置」这件事保住了。

## 3. 两条边界

1. **聚合视图（`/aggregate`）没有侧栏** —— 那 6 个目的地全是单作用域概念
   （既有约束，见 `App.tsx` 的 `bareShell`）。折叠态对它无意义，代码上天然不冲突。
2. **折叠不改路由、不改能力门控** —— URL 直达仍然可用（`/s/wb-cn/gateway` 照样到网关页），
   平台能力过滤（Trae 无「会话」）也不动。折叠只影响「看得见」，不影响「到得了」。

## 4. 无障碍

- 折叠态每个导航项都有 `aria-label`（读屏器不依赖视觉）；
- 折叠开关带 `aria-expanded` + `aria-controls`（状态可被辅助技术读出）；
- tooltip 只是**视觉冗余**（`title` 属性 + Radix Tooltip），不是唯一信息源 ——
  图标按钮的 `aria-label` 才是。

## 5. 验收

| 项 | 结果 |
|:--|:--|
| 原型行为断言（`verify-sidebar-collapse.cjs`） | **5 / 0**（展开态形态、折叠态形态、徽章角标、折叠态可跳页、开关两态） |
| 变异（3 个） | `badgelost`（折叠态丢徽章）/ `textkept`（折叠态仍渲染文字）/ `nodeadend`（开关失效）—— 全部被目标断言打红 |
| 原型回归（11 套件） | 全绿 |
| `npm run check:scope` | **324 / 0** |
| 真机 `tsc --noEmit` + `npm run build` | 通过 |

★ 变异踩过的两个坑（写进了套件注释）：**变异必须是「真的坏了」**
（第一版 `badgelost` 只加了个无害属性 ⇒ 空转，断言当然打不红）；
`expectRed` 要用**断言的唯一子串**（第一版写「折叠态导航没有文字」，
真实断言名是「折叠态：侧栏 64px、导航没有文字、每项带 tooltip」⇒ 名字对不上就被误判为「没打红」）。
