# 密钥访问权限管理 · 界面与交互设计（issue #76）

> 状态：**待拍板**（交互与视觉已成型，数据契约与实施拆解见 §6–§8）
> 原型：[`../prototype/key-permission-design.html`](../prototype/key-permission-design.html)（可直接打开，点得动）
> 校验套件：[`../prototype/verify-key-permission.cjs`](../prototype/verify-key-permission.cjs)（17 条行为断言 + 3 个变异）

## 1. 需求

issue #76「增加密钥访问权限管理功能」两条：

1. **根据密钥设置 token 可用量** —— 这把密钥最多能消耗多少 token。
2. **可限制密钥可访问的指定帐号列表** —— 这把密钥只能落到哪些账号上。

面向的用户是**把自己的网关分给别人用**的人：给自己写脚本、给同事发一把 key、给 CI 发一把 key。
今天这些 key 全是「万能」的——谁拿到都能用你的号、用你的额度，出了问题无法定位是谁用掉的。
本设计要解决的就是这两件事，且**不新增一级页面**。

## 2. 设计决策（先说结论与理由）

| # | 决策 | 理由 |
|:--|:--|:--|
| D1 | **不新增页面**：权限挂在现有密钥行上，用右侧抽屉编辑 | 权限是**密钥的属性**，不是新资源。密钥分区现有形态是「工具条 + 裸表 + 说明段」（见 `src/components/gateway/api-key-table.tsx`），再加一页会让用户多学一次「去哪儿找」。 |
| D2 | 把「创建时间 / 最后使用」**压到名称下方次行**，腾出两列给「用量」和「权限」 | 原表 7 列已经接近 1440px 宽度的极限；直接加两列会出横向滚动。压成次行后仍是 7 列，宽度不变，信息一条不少。 |
| D3 | 权限列用**两枚可点 chip**（额度 / 账号），不是一枚摘要 | 两枚 chip 各自独立可读（`额度 100万` `账号 3 个`），且**点哪枚就跳到抽屉的哪一段**——比一枚拼起来的摘要 chip 好点。 |
| D4 | 配额三档：**不限 / 累计上限 / 每日上限** | 「不限」保住今天的行为（老用户零感知）；「累计」对应「这把 key 一共只能用多少」；「每日」对应「今天给同事封顶多少」。不做「每周/每月」——单位越多，用户越难判断哪个是想要的。 |
| D5 | 数值单位**中文优先「万」**（`100万` 而不是 `1M`） | 中文语境里「100 万」比「1M」好读；≥1 亿才用 M。编辑框里同一个值不该在「100」和「1」之间跳。 |
| D6 | 账号范围两态：**全部账号 / 指定账号**（白名单） | 只有这两种，没有「排除某些」的第三态。白名单是**默认安全**的方向（漏配 = 不给权限，而不是给全量）。 |
| D7 | 「指定账号」但**一个都没选** ⇒ **禁止保存** | 空白名单 = 这把 key 永远选不到号 = 静默 404/无号可用。用户以为配好了，实际全废。 |
| D8 | 把上限改到**低于已用量** ⇒ **允许保存**，但明确警告「保存后立即超限」 | 有时就是要立刻掐掉这把 key。拦着不让存反而让人绕路。但必须把后果说清楚。 |
| D9 | 超限的请求被拒（429），**只影响这把 key** | 错误体要写明是哪把 key、配额多少，让客户端能自己停；其它 key 不受影响。 |
| D10 | 创建对话框里也带这两项设置 | 否则用户得「先创建、再编辑、再保存」三步走。默认值仍是「不限 + 全部」，与今天一致。 |
| D11 | 三条产品线（WB / Trae / Qoder）与统一网关**共用同一构件与文案** | 仓库既有铁律：三个 Key 表共用 `KeysBar`、共用 `shared.gateway.keys.note`。本设计不引入第四份实现。 |

## 3. 信息架构

```
密钥分区（现有形态，不动骨架）
├── 工具条：共 N 把 · M 把启用  +  [创建密钥]
├── 表格（7 列）
│   ├── 名称（次行：创建于 · 最后使用）        ← D2
│   ├── 归属（国内版 / 国际版）
│   ├── 密钥（掩码 prefix••••suffix）
│   ├── 用量  ← 新增：进度条 + 已用/上限 + 剩余
│   ├── 权限  ← 新增：额度 chip + 账号 chip（均可点）
│   ├── 状态（启用 / 接近上限 / 已用尽 / 已吊销）
│   └── 操作（编辑 / 吊销 / 恢复 / 删除）
└── 说明段（掩码口径 · 配额口径 · 账号范围口径）

抽屉「权限设置 · <密钥名>」（右侧，宽 440）
├── ① Token 配额
│   ├── ○ 不限
│   ├── ○ 累计上限  [数值] [单位]   快捷：10万/50万/100万/500万
│   ├── ○ 每日上限  [数值] [单位]   快捷：10万/50万/100万
│   └── 说明条（含「保存后立即超限」警告态）
└── ② 可访问账号
    ├── ○ 全部账号（沿用网关选号策略）
    ├── ○ 指定账号
    │   ├── 搜索框 + [全选] [清空]
    │   ├── 账号列表（复选；显示 名称 / 昵称 / 积分 / 状态）
    │   └── 已选 chips（可单个移除）
    └── 说明条
└── 底部固定条：预览句 + [取消] [保存]
```

### 3.1 列表的用量列

| 状态 | 判据 | 视觉 | 文案 |
|:--|:--|:--|:--|
| 正常 | `used/limit < 80%` | 主色进度条 | `62万 / 100万` + `剩余 38万` + 脚注「累计用量」 |
| 接近上限 | `80% ≤ used/limit < 100%` | 警告色进度条 + 徽标 | 同上 + 徽标「接近上限」 |
| 已用尽 | `used ≥ limit` | 危险色进度条（满）+ 徽标 | `100万 / 100万` + 徽标「已用尽」 |
| 不限 | `mode = unlimited` | 无进度条 | `不限` |

脚注区分「累计用量」与「今日用量 · 次日 00:00 重置」——两者不能混读。

### 3.2 抽屉

- **为什么是抽屉不是对话框**：要放多选账号列表 + 数值输入 + 说明，对话框会被撑到滚动；抽屉右侧展开、内容分区清楚，且与账号详情抽屉（`account-detail-drawer.tsx`）同构。
- **底部预览句**是必答题：保存前把后果说清 ——「保存后，『我的笔记本』的请求只会使用 3 个指定账号，配额累计 100 万 tokens。」
- **ESC / 遮罩可关**（与账号详情抽屉一致）。

### 3.3 账号选择列表

- 每行：勾选框 · 头像 · 名称 + 昵称 · 积分 · 状态（正常 / 冷却中 / 已禁用）。
- 搜索：按名称 / 昵称 / UID 三路匹配（与账号页搜索同口径）。
- 「全选」作用于**当前搜索结果**（不是全池）——用户搜完再全选，意图明确。
- 已选 chips 区可单个移除；0 选中时区里写「还没有选择账号」。

| 位置 | 文案 |

| 抽屉标题 | `权限设置 · <密钥名>` |

| 分区 ② | `可访问账号` |
| 选项 | `全部账号` / `指定账号` |
| 选项说明 | `沿用网关当前的选号策略，在全部可用账号里挑。` / `这把密钥只落到勾选的账号上；未勾选的账号不会被它消耗。` |
| 空选提示 | `至少要选一个账号，否则这把密钥永远选不到号。` |
| 超限警告 | `保存后立即超限（已用 62万 ≥ 上限 10万）：这把密钥的请求会立刻被拒（429）。` |
| 预览句 | `保存后，「<名称>」的请求只会使用 <全部可用账号 / N 个指定账号>，配额 <不限额 / 累计 100万 tokens / 每日 50万 tokens>。` |
| 列表说明段 | `掩码口径：仅显示前缀与尾部 4 位，明文只在创建时出现一次。配额按这把密钥实际消耗的 token 计（含客户端与网关两侧），不按账号总量摊。账号范围为「指定」时，这把密钥不会落到未勾选的账号上（白名单外不参与选号）。` |

### 4.2 网关侧错误文案

超额拒绝沿用既有错误信封风格（`GatewayError` / `openai_error`）：

```json
{"error": "quota_exceeded", "key": "my-laptop", "used": 1000000, "limit": 1000000, "resetAt": null}
```

- `resetAt`：每日配额时给下一重置时刻（`null` = 累计配额，无重置）。
- 账号范围不匹配（白名单外的账号被选号选中）⇒ **不静默换号**，按现有 fail-closed 口径报「无可用账号」，错误体里带 `scope` 说明。

## 5. 可访问性

- 抽屉：`role="dialog"` + `aria-modal` + 焦点移入 + ESC 关闭；标题与分区用 `h2/h3` 串成层级。
- 账号列表项：`role="checkbox"` + `aria-checked`，**空格/回车可切换**（原型已实现）。
- 进度条：`role="progressbar"` + `aria-valuenow/valuemin/valuemax` + `aria-label`（如「Token 配额，已用 62%」）。
- 颜色不是唯一信号：进度条之外始终有**数字 + 文字徽标**（接近上限 / 已用尽）。
- 所有可点 chip 同时是 `<button>`（原型用 `span.chip`，实现时换 `Button variant="ghost"`），键盘可达。

## 6. 数据契约（后端建议）

### 6.1 密钥记录扩展

`crates/buddy-switch-gateway/src/apikey.rs` 的 `ApiKeyRecord` 增补（**全部 `#[serde(default)]`**，老台账零迁移）：

```rust
#[serde(default)]
pub quota_mode: QuotaMode,        // Unlimited | Total | Daily
#[serde(default)]
pub quota_limit: u64,             // token 上限（Total/Daily 有效）
#[serde(default)]
pub scope_mode: ScopeMode,        // All | Selected
#[serde(default)]
pub scope_accounts: Vec<String>,  // 允许访问的账号 uid（Selected 有效）
```

`masked()` 的线上形态同步补三个字段：`quotaMode` / `quotaLimit` / `scopeMode` / `scopeAccounts` / `quotaUsed`。

### 6.2 用量计数

- 计数按**这把密钥**累计，落 `~/.buddy-switch/gateway_key_usage.json`：`{ keyId: { total, daily: { yyyy-mm-dd: n } } }`。
- 记账点与用量页同源：`UsageTap`（流结束）——**不能**在请求前记（请求可能失败）。
- 每日重置以**本地时区**的日期为键；读的时候若 `daily` 的键不是今天 ⇒ 视为 0。
- 配额判定点：请求**进入网关后、选号前**。超限 ⇒ 429，且**不消耗选号额度**（不占在途、不触发换号）。

### 6.3 选号与白名单

- 白名单是**硬约束**：在 `pick_account` 的候选过滤阶段剔除 `scope_accounts` 之外的账号（与既有的 `excluded` 用户显式排除同层，但**来源不同**：一个是用户排除全局，一个是本 key 的允许集合）。
- 作用范围：**只对这把 key 的请求**生效；不改变账号池本身，不影响其它 key。
- 白名单里的账号若已冷却/禁用 ⇒ 视为不可用（不特殊照顾）。

## 8. 验收用例

**原型侧**（`verify-key-permission.cjs`，17 条已全绿）：

1. 列表渲染全部密钥，工具条计数与行数一致。
2. 每行都有用量 + 权限两列实体；chip 必须可点。
3. 「不限」不画进度条。
4. 百分比渲染正确（62% / 86% / 100%）。
5. 状态徽标：接近上限 / 已用尽。
6. 点 chip 开抽屉，两个分区都在。
7. 「指定账号」才出现账号列表。
8. 勾选后已选数与预览同步。
9. 取消勾选计数回落（带前置断言，防恒真）。
10. 0 选中 ⇒ 保存禁用 + 给出原因。
11. 选回「全部账号」⇒ 列表收起、保存恢复可用。
12. 改额度 ⇒ 预览同步。
13. 上限低于已用量 ⇒ 提示「立即超限」。
14. 保存 ⇒ 行内 chip 与用量条同步。
15. ESC 关抽屉。
16. 创建对话框可开、可填名、可创建。
17. 创建对话框可选配额模式。

**后端侧**（待补）：

- 超额请求 ⇒ 429 + `quota_exceeded`，且**不**占用选号在途额度。
- 每日配额跨日归零（本地时区）。
- 白名单外的账号**不会**被选中；白名单内全不可用 ⇒ 报「无可用账号」而不是回退到全池。
- 策略变更**立即生效**（存储每次操作实时读盘，不缓存）。
- 老台账（无新字段）加载后行为 = 「不限 + 全部」。

## 9. 明确不做（本期）

- 配额**按模型**细分（不同模型不同单价/不同额度）。
- 账号范围的**排除模式**（黑名单）。
- 配额**周期**扩展到周/月/自定义周期。
- key 之间的**共享额度池**（多个 key 共用一个预算）。
- 审计日志（谁在什么时候用掉了多少）—— 依赖网关请求日志的扩展，另立 issue。
